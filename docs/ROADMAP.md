# forest3D · V0.3 至 V1.0 迭代计划

## 目标与范围
打造可公开分享、适合手机的沉浸式互动森林。优先级：视觉品质 → 互动自然度 → 声音 → 性能稳定 → 内容数量。
正式版保持 2.5D，三个场景（日光森林、萤火之森、雨后溪谷）、一个统一角色（待机/眨眼/挥手/跳跃/抬头/聆听）、灯串/蘑菇/溪流互动、音乐/环境/交互声、加载降级与分享部署。不加入登录、数据库、任务、积分、收集或复杂 HUD。

V0.1/V0.2 已提交；V0.2 基线 25a6e88。GitHub origin 已连接到 Minervaxchan/forest3D；本记录不推断远端可见性。源码保持私有为正式发布要求，需在仓库设置确认。当前交付 V0.3 开发版，待人工体验确认。

## 技术约定
保持 React、TypeScript、GSAP，不提前引入重型 3D 依赖。
- SceneConfig 管理资源清单、移动端锚点、互动对象和环境反应；场景注册表统一目录与加载。
- 角色使用语义动作与完成/取消生命周期。位置由场景管理，将来 sprite/GLB 共享动作语义。
- 用户操作优先；自动反应最多等待一个，切场景清除。
- 核心资源失败可重试，可选失败降级，取消过期加载；音频不阻塞进入。
- 只保存静音和首次提示状态；存储不可用不阻塞。
- 音频保留独立场景混音、总静音、外部素材与合成备用。
- 素材保留作者/来源/授权/提示/源文件/压缩版，正式音频不得来源不明。

## 每版与正式版验收
每版：可运行构建、实现文档、截图/短录屏、build/lint/受影响自动化、390×844 与 1440×900、素材与未完成清单、独立可回退提交。
正式版额外：
- 真实 iPhone 与中端 Android 完整流程，以及微信内置浏览器；传感器拒绝/不可用始终保留拖动。
- 十分钟连续体验、二十次切换无明显音源或内存持续增长。
- 常规接近 60fps，指定中端机持续交互平均 ≥50fps，低端降级仍流畅。
- 首场景必要压缩资源目标 ≤1.5MB；约 10Mbps/100ms 网络冷启动目标三秒可进入，以实测优化。
- 弱网、资源失败、后台、静音、reduced-motion 都有可用路径。
- 听感和美术必须人工评审，控制台无错不是替代。

## 部署、权限与外部依赖
默认私有 GitHub 源码库 → GitHub Actions → Cloudflare Pages，仅发布 dist；PR 检查，同仓库分支预览，验收合入 main 后生产部署。保留上一稳定构建与回退流程，发布失败不影响当前站点。
方案参考：https://developers.cloudflare.com/pages/how-to/use-direct-upload-with-continuous-integration/ （实施 V0.7 时再核对官方步骤）。
需要 GitHub 权限、Cloudflare 账号与部署令牌；令牌只放平台密钥。默认托管 HTTPS 域名，自定义域名不阻塞。网页及运行时素材公开，原始参考、高分辨率源图和测试文档不部署。
开发负责技术验证，项目负责人负责美术、听感与版本确认；真实手机、五位体验者和账号权限是外部依赖，不伪造验收记录。首发暂不接用户追踪，使用部署记录、发布冒烟和人工反馈。
新增玩法先入待办，不插入当前迭代。

## V1.1 独立 GLB 实验
仅在 V1.0 稳定后进行：一个角色的模型/材质/绑定/动作，按需局部 3D、森林继续 2.5D；对比外观、首屏体积、帧率；失败使用图片角色。视觉和性能均通过再考虑替换，否则保留实验，不阻塞正式版。
